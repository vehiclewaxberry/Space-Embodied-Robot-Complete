# B5.1R1 Phase 2A fail-closed 与恢复策略

状态：`PREPARED_NOT_AUTHORIZED / G1_HOLD`

本策略只定义未来已获授权会话的异常边界，不授予任何启动、附着、保存、终止进程或 CAD 写入权限。

## 1. 总原则

1. 每个 S01..S06 会话是独立作用域；异常不能借“恢复”扩大当前授权。
2. 所有恢复先保存只读证据，再决定是否在当前授权内继续；不确定时立即停止。
3. 不删除、覆盖或重写受保护输入、历史失败收据或已通过的独立检查点。
4. 不通过复制旧零件、移动旧桥接件、Move Component、Transform2、Fix Component 或新增第二驱动来掩盖失败。
5. 每次失败记录：会话、Gate、精确阶段、进程 PID、文档标题、目标路径、调用计数、错误/警告、前后 SHA-256、已关闭文档数和最终进程状态。

## 2. 恢复对话框

- 会话开始前 SolidWorks 进程必须为 0。
- 若新进程出现恢复对话框，只能在该会话授权明确允许的情况下清除；不得打开、恢复或保存不在当前会话输入清单内的文件。
- 无法证明对话框内容和处理结果时：`FAIL_CLOSED_RECOVERY_DIALOG_HOLD`，正常退出当前精确进程。
- 清除对话框不增加启动额度，不授权重启；再次启动需要新的明确授权。

## 3. API hang 或无响应

- 记录最后一个已开始和已完成的 API 调用、超时阈值来源、精确 PID、窗口标题和目标文件哈希。
- 首选受控 API 关闭；若失败，只能在当前人类授权明确涵盖 containment 时终止本会话创建的精确 PID。
- 禁止按进程名批量终止、终止未绑定 PID、重启系统或自动再次启动 SolidWorks。
- 精确 PID 消失后再次确认 SolidWorks 进程数；保留 incident，当前 Gate 失败。
- API hang 后不得在同一进程中继续建模。

## 4. 保存错误、警告或哈希异常

- `Save3` 或等效受控保存出现非零错误/警告即停止；不得重复保存直到“碰巧成功”。
- 记录保存前后字节数和 SHA-256。哈希变化本身不自动通过或失败，必须重新验证所有语义不变量并说明只有一次受控保存。
- 目标路径、文档标题或扩展名不一致时不得关闭错误文档后继续；先形成 incident。
- Stage A、accepted URDF 或任一锁定输入哈希变化：立即 `FAIL_CLOSED_PROTECTED_INPUT_MUTATION`，禁止后续会话。

## 5. Mate 翻转、冗余和多驱动

- 首个 Mate 翻转、符号相反、冗余约束、求解失败或多驱动即停止在对应 Jxx 检查点。
- 不添加辅助角度/距离 Mate、锁旋转、Fix Component、Mate Controller 或绝对组件变换来强行稳定。
- 保留最后一个已通过检查点和失败检查点副本/收据；不得覆盖前者。
- 根因只能在离线审查后由新的、明确授权会话修复；原授权不自动包含重做。

## 6. Carrier 单件失败

- S03 或 S04 在首个失败 Carrier 停止；此前通过的 Carrier 保留且只读。
- 不跳过失败件继续声称 10/10，不用 STEP 或静态几何替代原生特征。
- 恢复必须从失败件开始，但是否重开同件或重建必须由新的授权明确说明。

## 7. T005 异常

- A0 位形不独立、B0 同文档连续驱动中断、q0 返回失败或 C0 冷重开失败均独立判失败。
- C0 通过不能覆盖 B0 失败；重开后正常不能证明同文档连续驱动。
- 任何位形若来自 Move Component、Transform2 或未受控抑制状态，不授予 T005 信用。

## 8. 正常退出证据

- 使用当前文档真实标题关闭；确认文档数为 0。
- 调用受控应用退出并确认精确 PID 消失、SolidWorks 进程总数为 0。
- 外部进程退出码不可用时，只能在 `HasExited` 或精确 PID 消失和进程总数为 0 均被证明时记录为非阻断；不得虚构退出码。
- 强制终止不得被描述为“正常退出”。

## 9. 恢复后的结论限制

恢复成功只关闭具体 incident，不自动升级 Gate，也不自动授权下一会话。任何新写入、重开或启动都必须同时满足：输入锁、人工 datum/命名/容差权威、对应会话授权和上一 Gate 通过。
