## 3. 七个逻辑角色，不等于同时开七个重进程

A0 ORCHESTRATOR：锁定任务、证据快照、分配问题和停止点；不以投票决定物理事实。
A1 CONFIG_AND_FILES：权威、依赖、版本、文件分类与整理风险；不写CAD、不删文件。
A2 STRUCTURE_REVIEWER：孔/槽/紧固/接触、真实连接与载荷路径、维护可达性。
A3 MECHANISM_REVIEWER：双保持器、臂/翼/线束、驱动和故障状态、连续路径。
A4 VNV_CODE_REVIEWER：验证器、范围、hash链、负控、独立重算；不修改被审CAD。
A5 SYSTEM_DYNAMICS_REVIEWER：质量惯量、自由漂浮耦合、ADCS/推进/电/热/感知接口与研究可继承性。
A6 CAD_BUILDER：唯一CAD/参数生产写入者；只在授权的派生候选执行最小修改，不更改判据。

初始审阅最多并行2个轻量任务；重计算最多1个；一个任务不得同时兼任自身最终验收者。Codex可任A0/A6，Claude可任A4等，但以可用权限/额度为准。不能调用的角色记为未执行，不伪装成独立Agent意见。角色可串行执行。

给每个角色相同的基线ID、输入哈希、范围与待证命题。先各自形成可证伪意见，再交换。审阅者必须列出一个反例或具体检查；“看起来合理/不合理”不作为证据。意见格式统一，写入同一个问题账本，不让每个Agent再建一个CURRENT。

## 4. 对抗式问题与严格结论口径

每项用三层证据：
1. `DOCUMENTED`：原文确实这样报告；
2. `INDEPENDENTLY_REPLAYED`：同源模型由独立检查复验；
3. `HARDWARE_VERIFIED`：明确仪器、工况及实物版本的试验。
再单独记录“推断/风险/待验证”。不把UNKNOWN改成FAIL，不把无反例改成PASS。

### A. 总体、产品与状态
- GSE是否完全从随星质量、外包络、惯量和载荷边界排除？
- 支持主任务的结构、保持/释放、翼、供能/数据、姿控、通信/感知、热及发射接口是否都有责任实体或显式代理？
- 侧伸的折退架是当前机构功能还是不必要负担？计算其部署后质量、惯量、悬臂柔度、视场/翼遮挡和夹挤；不能凭截图直接删掉。
- 发射收拢与当前开放停放分开；没有包络/供应方/载荷时保持发射HOLD，不重启无限裸臂12U优化。

### B. 连接与结构
- 两层甲板各两个破边孔及相应角材、螺钉头/垫圈承压区一起重设计；可以设计明确的开放槽，但必须单独给定位、承载和防脱依据，不能重命名成槽后宣称关闭。
- 建立实体连接图：臂根→M3R→桥/横梁→主框/端框→分离接口保留区。边必须对应安装面、定位/紧固/接触方式，不以零距离、公共体积0或parent_assembly替代。
- 每条边记录约束方向、对偶孔、螺纹/有效啮合、工具路径、候选预紧与缺失输入。
- 地面固定、发射端固定、自由体与已保持机械臂分开建模。单位载荷柔度不升级为强度、疲劳或飞行合格。

### C. 机构与路径
- 26 mm退销、80 mm下退、100°开盖、90°折退都有实际导向/驱动/止挡/防脱/终位结构吗？
- 下鞋导杆端部、执行器安装、固定侧到随动侧线束能否在全部状态保持连接？
- 6种功能包络候选：使用实选或尺寸约束严密的代理，不能通过隐藏功能盒消掉冲突。
- 22种物理OBB候选：逐对精检空腔、孔、轴、槽；允许接触需按部位与状态列白名单，不能整类豁免。
- 至少检查单站未释放、销未退出、盖开而下接触未解除、确认矛盾、失电、线缆约束、退出后回弹等负控；不可假定掉电自锁或自动回夹。
- 全动作链使用同一对象清单、坐标、线束长度/固定点和实际路径；有限采样明确为采样，连续保证需要保守运动界或可靠连续算法。最小净空必须绑定误差预算，不编造默认1 mm容差。

### D. 几何验证器
- 179物理实例、361装配实例、742叶实例、145零件文件分别定义分母。数量不同并非自动矛盾，但不得换分母报完成率。
- 检查完整10-link/双指与全部已包含星体件；BRep、accepted STL与实物接口不互相冒充。
- 179非臂通过不覆盖臂；相邻link整对忽略会漏掉接口之外的穿透，使用局部允许接触。

## 5. Loop engineering：固定判据的小闭环，不是无限自评

每个issue执行：
`OPEN → EVIDENCE_BOUND → REPRODUCED / INPUT_BLOCKED → PATCH_PROPOSED → CANDIDATE_BUILT → INDEPENDENT_CHECK → MERGED_IN_CANDIDATE / REOPENED / ESCALATED`。

每轮输入：一个最小问题、锁定配置、最小反例、允许变更文件、受影响接口、冻结的接受判据。
每轮输出：最小diff、独立检查原始结果、相关回归、质量/几何/依赖增量和剩余未知。

接受判据：反例消失、必需对象/配对未减少、输入同源、负控仍被拒绝、无新增相关阻断；不是“作者说完成”或Agent多数投票。

建议每个问题最多3次尝试，连续2次指标无改善就定位/升级；这些是调度预算，不是工程合格阈值。明确缺输入时只阻塞相应结论。402/余额或权限失败停止该分支，禁止多路盲目重试；普通瞬时错误最多1次受控重试；timeout不计PASS。

审阅者不得降低目标让构建者通过。验证器有bug时单开票修验证器，保留修前/修后反例，并重新审核相关结果。不得在同一个未解释diff中同时改CAD和接受阈值。

阶段建议：
- Loop0：同源证据绑定、验证器负控、依赖导航；原CAD不变。
- Loop1：甲板孔/避让/角材/紧固与根框连接的最小局部改件。
- Loop2：随星保持器真实连接、执行器与退出后保持；6+22配对逐项归因。
- Loop3：同配置臂—保持器—翼—线束的完整对象/路径与误差预算。
- Loop4：新结构与逐link质量惯量、姿控/能源/热/任务接口交接。
- Loop5：冷环境重建与逻辑归档；只有依赖解除后再讨论物理去重。
不能为满足Loop编号而把本来独立的外部输入阻塞扩大成全项目停工。

新导航优先写在会话内，经过检查后才晋升现有current入口：
- 当前完整总装和允许用途；

可重建不代表原始字节必然一致。输入和冻结证据必须字节一致；STEP重新序列化后可出现新hash，应登记最终实际产物，并比较单位、名称/实例、变换、接口尺寸、体积/包络和质量所有权的语义不变性，不能伪造旧hash。

## 7. 关闭定义与交付

技术判断按用途分开：
- 可以继续：接口补图、参数化最小改件、离线验证器、有限路径诊断、带显式未知参数的多体研究。
- 需要补证据：完整整星无碰撞、可执行保持释放、连接承载、完整姿控/能源/热能力。
- 仍不允许声称：制造发布、实物承载通过、发射收拢完成、特定部署器适配、空间环境资格或旧控制结果适用于WP03。

最终只需一份总览和三个共享机器账本，不追求报告数量。总览先回答：
1. 哪些原始结果独立复验，哪些仅为引用，哪些失败/未知？
2. 第一张允许改的零件票是什么，具体对偶件和通过条件是什么？
3. 哪条研究线可以继续，参数缺项与不许外推的结论是什么？
4. 文件分类统计按真实范围分别多少；哪些旧目录是活动依赖？
5. 是否存在未经授权写入、缺失任务、同源失败或角色额度失败？
6. 下一轮最小变更集与外部输入请求是什么？

用户应得到一个能打开的整星入口、一条确切可执行问题链，而不是再次得到“建议再审计”的循环。
